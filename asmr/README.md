# ASMR 直播舞台

一个不露脸的 ASMR 直播间：**真人的手 + 胸口 + 真实房间**的视频画面，**真人声线的耳语**回应弹幕，声音会在观众的左耳、右耳之间移动，敲击、毛毡、刷子这些触发音和画面同步出现。

和仓库里原来的 DSH 语音女友是两套东西：这里不依赖 DSH，也不需要数字人口型模型，Mac 上就能跑通整条链路（真人声线的 TTS 跑在你租的 GPU 上）。

```
弹幕 ──▶ 导演（LLM）写一行带标签的耳语台词
          [左]小明…晚上好呀[敲击][右]今天也辛苦了吧…[毛毡]
             │
             ▼  render.py
   耳语 TTS（真人声线克隆） ──▶ 双耳空间化（左耳/右耳/绕头）
   触发音：素材片段自带的录音，或 sounds/ 里的录音
             │
             ▼  48kHz 立体声 WAV + 提示时间轴
   舞台网页：底层循环 idle 片段，每个提示点准时切到对应动作片段
             │
             ▼
   直播伴侣 / OBS 采集这个窗口和它的声音
```

## 快速开始（Mac）

先起本地耳语声线服务（第一次会装依赖、下载约 5GB 模型），再起舞台：

```bash
uv venv venv-tts --python 3.12 && uv pip install --python venv-tts/bin/python mlx-audio fastapi uvicorn soundfile
```

```bash
venv-tts/bin/python -m asmr.tts_server --voice whisper
```

```bash
./asmr/start-asmr.sh
```

- 舞台：<http://127.0.0.1:8770/>，点一下解锁声音。加 `?debug=1` 显示状态，`?caption=0` 隐藏字幕，`?lights=0` 关掉灯光叠加，`?palette=lavender` / `blue` 换灯光色调（默认紫色）。
- 中控台：<http://127.0.0.1:8770/control>，可以发模拟弹幕、一键插播敲击/毛毡/灯光，也可以手写脚本插播。
- 戴耳机听。

声线服务没起来时会自动退回 macOS 自带语音；没有任何素材时，会用程序画的占位画面。

配置：把 `asmr/asmr-config.example.json` 复制为 `asmr/asmr-config.json` 再改（这个文件不会被提交）。接 LLM 需要设置 `DEEPSEEK_API_KEY` 环境变量，或者填 `llm.api_key`；不填时用内置的备用台词。

## 一、画面素材：真人的手 + 胸口 + 真实背景

### 每天换装

每套服装一个文件夹，按天自动轮换（按文件夹名排序，一天一套）；中控台的「今日服装」可以固定某一套：

```
asmr/media/outfits/1-lavender-knit/idle/still.jpg      待机：还没有视频时用静态图（会轻微“呼吸”）
asmr/media/outfits/1-lavender-knit/idle/*.mp4          待机视频（有就优先用）
asmr/media/outfits/1-lavender-knit/ear_massage/*.mp4   各动作片段
asmr/media/<动作>/*.mp4                                 所有服装共用的备用素材
```

| 动作文件夹 | 内容 | 时长建议 |
|---|---|---|
| `idle/` | 待机：自然呼吸、手轻放在假耳朵上 | 5–60 秒 |
| `whisper/` | 耳语时播放（循环）：身体微微前倾靠近麦克风 | 4–10 秒 |
| `ear_massage/` | 揉捏按摩两只假耳朵 | 4–6 秒 |
| `ear_pick/` | 掏耳朵 | 4–6 秒 |
| `ear_brush/` | 用软刷扫耳朵 | 4–6 秒 |
| `tap/` | 指尖轻敲，**左右手交替** | 3–6 秒 |
| `felt/` `brush/` `breath/` | 搓毛毡 / 刷子 / 一次缓慢呼吸 | 2–6 秒 |
| `lights/` `guide/` | 实拍的交替灯光 / 呼吸灯 | 3–20 秒 |

哪个文件夹没有素材，那个动作就只有声音、不切画面。只要有待机素材（视频或静态图），程序画的占位手就不会再出现。

### 用 AI 生成（本仓库的实际做法）

1. **定妆照**：在 ChatGPT 里生成一张基准图（锁骨以下入镜、不露脸、紫色冷光、双手放在双耳麦的假耳朵上），再让它「保持场景、灯光、机位完全一致，只换衣服」，一次做出一周的换装图。
2. **动作视频**：用 MiniMax H3 的「首尾帧」工作流（`~/ai-video-lab` 的 Modal ComfyUI 工作室），**首帧和尾帧都用同一张换装图**，提示词描述这个动作和同期声（Sound: …）。生成的片段首尾画面一致，和待机画面无缝衔接，H3 自带的同期声直接当触发音用。
3. 用 `prepare_clips --outfit <服装>` 归档。

用工具把原始视频整理成舞台需要的格式（9:16、1080×1920、30fps、浏览器能秒开）：

```bash
venv-asmr/bin/python -m asmr.tools.prepare_clips raw/tap_01.MOV --action tap
venv-asmr/bin/python -m asmr.tools.prepare_clips raw/idle.MOV --action idle --trim 3.5 48
venv-asmr/bin/python -m asmr.tools.prepare_clips raw/felt_ai.mp4 --action felt --no-audio
```

### 实拍（最逼真，推荐）

- **构图**：竖屏，固定机位（三脚架），从胸口拍到桌面，脸不入镜。手动锁定曝光、白平衡和对焦，不然切片段时画面会跳。
- **场景**：真实房间，左右各放一盏暖色台灯（拍 `lights/` 用，也可以用能分别控制的智能灯），桌上放毛毡垫，双耳麦入镜也很有 ASMR 感。衣服用纯色、不反光的。
- **衔接**：每条动作素材都**从同一个待机姿势开始，回到同一个待机姿势结束**。这样从 idle 切到动作、再切回来是无缝的（切换只有 0.35 秒的交叉淡化）。
- **同期录音**：用双耳麦同时录声音。**素材自带的声音会直接当作触发音**，画面和声音来自同一条，天然同步，也最真实。不想要原声就加 `--no-audio`。

### AI 生成（没法实拍时）

1. 先准备一张「首帧」图：实拍一张，或者用 AI 生成（胸口以下、双手放在毛毡上、真实房间、暖光）。
2. 用图生视频模型（可灵、即梦、Wan 等），**把同一张图同时设为首帧和尾帧**，逐个生成每个动作。所有片段都从同一画面开始、回到同一画面，切换才不会穿帮。
3. AI 视频没有声音，触发音用 `asmr/sounds/` 里的真实录音配（见下一节）。
4. 多段生成时要特别检查手部：手指数量、形状，以及前后片段是否一致。

## 二、触发音

优先级：素材片段自带的声音 > `asmr/sounds/<名字>/*.wav` 的录音 > 程序生成的占位音。

在 `asmr/sounds/tap/`、`felt/`、`brush/`、`breath/` 里放真实录音（多条随机挑选）。单声道录音会被放到对应的耳朵位置；敲击声会左右交替出现。

## 三、真人声线的耳语

默认用 `local`：在 Mac 上本地运行 Qwen3-TTS（MLX 版）。音色是用文字「设计」出来的耳语女声，不需要真人录音：

```bash
venv-tts/bin/python -m asmr.tools.design_voice --name whisper --takes 3
```

```bash
venv-tts/bin/python -m asmr.tools.design_voice --name whisper --keep 1
```

第一条命令生成 3 个候选（`asmr/voices/whisper/candidates/`），听完用第二条选定一个作为参考音色。之后每句话都用 Base 模型克隆这个参考音色，整场直播音色一致。M4 上大约是 3 倍实时（2 秒的话要生成约 6 秒），空闲节目会填补等待；换到 GPU 上会快很多。

`tts.backend` 一共四种：

| backend | 用途 |
|---|---|
| `local` | `asmr/tts_server.py`，Mac 本地的设计声线（默认） |
| `say` | macOS 自带语音，只用于开发时跑通流程，不是耳语 |
| `http` | 任何「POST JSON → 返回 WAV」的 TTS 服务，示例配置是 **GPT-SoVITS api_v2** |
| `bridge` | 本仓库的 `bridge/voice_bridge.py`（OmniVoice / Qwen3 克隆） |

推荐在租的 GPU 上跑 GPT-SoVITS：

```bash
python api_v2.py -a 0.0.0.0 -p 9880
```

然后在 `asmr-config.json` 里把 `tts.backend` 改成 `"http"`，`tts.http.url` 改成 `http://<GPU服务器IP>:9880/tts`，`ref_audio_path` 和 `prompt_text` 填一段**耳语参考音频**和它逐字对应的文本。

想让耳语更自然：用 1–2 小时的耳语录音微调一个专门的耳语模型，效果比只拿一段参考音频克隆好很多。声音必须取得本人授权。

## 四、上直播

- 舞台页面是 9:16 竖屏。在直播伴侣或 OBS 里用「窗口采集」采集浏览器窗口，声音选采集这个窗口或桌面音频。Windows 云服务器上没有声卡时，装 VB-Cable 虚拟声卡。
- 音频是 48kHz 立体声，推流码率建议设到 192k 以上，否则双耳效果和细节会被压掉。
- 真实弹幕：写一个抓取脚本，把每条弹幕 `POST /api/danmaku {"user": "...", "text": "..."}` 发给舞台服务就行。中控台的模拟弹幕走的也是同一个接口。

## 脚本标签

| 标签 | 作用 |
|---|---|
| `[左]` `[右]` | 声音移到左耳 / 右耳旁边（很近） |
| `[中]` | 正前方 |
| `[绕]` | 从左耳慢慢绕到右耳 |
| 动作标签（见下表） | 慢慢持续做一段时间的触发动作；标签后加数字指定秒数，例如 `[耳朵按摩30]` |
| `[灯光]` | 左右交替的紫色灯光（默认 8 秒） |
| `[引导]` | 呼吸引导灯：中间的光 4 秒变亮（吸气）、6 秒变暗（呼气），默认 20 秒，配合「吸气…呼气…」 |
| `[停顿]` | 安静停一秒 |

### 动作库

每个动作都会**持续做一段时间**，不是刷一下就结束。时长的优先级：脚本里写的秒数 > 中控台「动作库」里单独设置的 > `asmr-config.json` 的 `"actions": {"ear_massage": 30}` > 默认值。中控台还有一个「全部动作时长 ×」倍率滑块。

| 类别 | 标签（默认秒数） | 声音怎么动 |
|---|---|---|
| ① 硅胶耳朵 | `[耳朵按摩]` 24、`[掏耳朵]` 24、`[棉签]` 20、`[刷耳朵]` 20 | 紧贴一只耳朵，每 6 秒换到另一只（写了 `[左]` / `[右]` 就只做那一侧） |
| ② 刷子 | `[刷子]` 18、`[羽毛刷]` 18、`[刷脸]` 15 | 刷子从一只耳朵慢慢扫到另一只；刷脸在正前方 |
| ③ 敲击 / 容器 | `[敲击]` 14、`[敲木盒]` 14、`[敲玻璃]` 14、`[拧瓶盖]` 12 | 左右手交替、慢慢一下一下地敲；拧瓶盖在正前方 |
| ④ 柔软材质 | `[毛绒]` 20、`[海绵]` 15、`[丝绒]` 18、`[毛毡]` 18 | 毛绒贴耳左右交替；丝绒、毛毡左右缓慢扫动 |
| ⑤ 纸张 | `[翻书]` 18、`[揉纸]` 14、`[气泡膜]` 12、`[胶带]` 10 | 翻书在正前方；气泡膜左右交替 |
| ⑥ 手部 | `[手套]` 18、`[搓手]` 14、`[护手霜]` 16 | 手套左右交替；搓手、护手霜在正前方 |

有视频素材的动作会把多段素材连起来播放，凑满设定时长（首尾帧相同的素材可以无缝衔接）；没有素材的动作先只有声音。

### 道具场景

需要道具上桌的动作（敲木盒、敲玻璃、拧瓶盖 → `knock`；毛绒 → `fluffy`；海绵、丝绒 → `soft`）属于一个「道具场景」。它们的素材首尾帧都是「道具已经摆好」的画面，所以播放时会自动接成：

```
scene_<场景>_in（摆上道具） → 动作素材 × N（凑满时长） → scene_<场景>_out（收走道具） → 回到待机
```

过渡素材放在 `asmr/media/outfits/<服装>/scene_<场景>_in/` 和 `scene_<场景>_out/`，用 H3 首尾帧生成：摆上道具的首帧是待机图、尾帧是道具场景图；收走道具反过来。

### 画面连贯（看不出循环和切换）

- **同一个接缝画面**：所有素材都以待机图（或道具场景图）作为首帧和尾帧，切换只发生在两个相同的画面之间，再加 0.25 秒交叉淡化盖住细微差异。
- **待机对齐**：舞台会提前微调待机视频的速度（0.8–1.25 倍），让它在动作开始那一刻正好回到首帧；动作播放期间，待机停在首帧等着，动作结束后从首帧接着播。实测接缝误差在 1 帧以内。
- **待机循环不闪**：把待机素材和它的倒放版本拼成一条 `idle/idle_loop.mp4`（中点也是首帧），整条循环播放，不切换视频源。
- **长动作不重复**：同一动作有多条素材时不连续播同一条；每条随机变速 0.9–1.1 倍（声音同步变速）。揉、搓、抚摸类动作用 `prepare_clips --reverse` 生成倒放版本，和正放交替播放（声音同步倒放）；敲击、翻书这类倒放会穿帮的动作不用。
- **耳语前倾不截断**：前倾片段按说话时长整段变速播放；话太短就不播，绝不在动作中途切回待机。

## 文件

| 文件 | 作用 |
|---|---|
| `server.py` | 服务、播放时钟、弹幕队列、空闲节目 |
| `director.py` | LLM 导演和脚本解析 |
| `actions.py` | 动作库：标签、默认时长、声音摆位，时长调节 |
| `render.py` | 把脚本渲染成双耳立体声 WAV 和提示时间轴 |
| `binaural.py` | 球形头部模型的双耳空间化（ITD、头部遮挡、近场） |
| `media.py` | 视频素材库，读取素材自带的声音 |
| `sounds.py` | 触发音（录音或程序生成的占位） |
| `tts.py` | 可插拔的 TTS |
| `tts_server.py` | Mac 本地耳语声线服务（Qwen3-TTS MLX） |
| `voices/` | 设计好的声线（参考音频和文本） |
| `tools/design_voice.py` | 用文字描述设计声线 |
| `stage/` | 舞台页面和中控台 |
| `tools/prepare_clips.py` | 素材整理工具 |
